## Architecture and trust boundary

A fictional federal mission-support team needs an offline reference assistant for readiness and restoration procedures. A single kind node hosts a single nonroot Python service, a ClusterIP service, a 128 MiB PVC for an integer request counter and a tokenless ServiceAccount with no granted RBAC permissions. The fixed synthetic employee identity uses the existing `app/authorization.py` audience logic. The client cannot choose an audience. It uses a local deterministic extractive retrieval backend with the existing RAG response shape (answer, abstention, sources); **no model inference, embeddings, Bedrock calls, or real authentication**. Two public fictional documents and one restricted canary are hardcoded. No request content is persisted or logged. The only supported access is the operator's authenticated kubectl loopback port-forward. This is not a production API; anyone who can reach the service can act as the fixed fixture employee. A real identity-aware proxy and tested network isolation are needed before wider exposure.

CPU request/limit 100m/500m; memory request/limit 32/128 MiB; read-only root FS, dropped capabilities, runtime-default seccomp, namespace restricted PSS. Recreate deployment prevents concurrent counter writers and intentionally accepts downtime. PVC is local ephemeral-kind storage, not encrypted or replicated storage. Egress-deny policy is declared but kind CNI enforcement is **not** asserted. The loopback-port-9 probe represents a fictional unavailable upstream, not actual external egress loss. The application is designed to have no external dependencies.

Threats: unauthorized document selection (fixed audience plus filter); request-content logging (only status and elapsed time); privilege escalation (nonroot, tokenless, restricted pod); malicious image/manifest changes (digest/checksum verification); failed readiness (rollback and endpoint check); node/storage loss (counter backup and restore). Remaining risks: no real auth, no signed bundle trust root, no CNI enforcement test, no high availability, no tested hardware enclave, no independently reviewed security controls, no production encryption or model-quality claims. Hashes identify artifacts, not publisher identity or signatures.

## Reproduction

Requires Docker daemon, kind v0.27.0, kubectl, Python 3.13, Git, and Linux shell. Run `PYTHONPATH=app:edge_lab python -m unittest discover -s edge_lab -p 'test_*.py' -v` for local contract/manifest tests. Full rehearsal is **only for a disposable runner** with no other cluster named edge29: `RUNNER_TEMP=/tmp bash edge_lab/rehearse.sh`. Do not run against an existing or shared cluster. It deletes and recreates kind-edge29. Base and node image digests are resolved and recorded at run time; for exact later reproduction retain the same digests, bundle and revision. Initial cluster bootstrap and optional scanners need internet. The application reinstall imports a checksummed saved image and manifest with imagePullPolicy Never, not a physically disconnected facility. Artifact retention 14 days; preserve externally if needed. The image tar is retained during the exercise, not uploaded by default.
